# 海外展開の方針と国別KPI

最終確認: 2026-08-08（iTunes Lookup API で実測）

## 診断：いま起きていること

**全8本が US / GB / DE をはじめ世界中で購入できる状態**になっています。
配信は止まっていません。問題は中身です。

| アプリ | 日本 | US / GB | ドイツ | アプリのUI言語 |
|---|---|---|---|---|
| 透けマル | 透けマル 背景透過 | Sukemaru: Verified Cutout PNG | **Sukemaru: Freisteller-PNG** | EN, DE, JA, KO, ZH |
| カエセル | カエセル 住宅ローン計算 | Kaeseru Loan Payoff Calc | 日本語のまま | EN, JA |
| シメキリ逆算 | シメキリ逆算 原稿・執筆 | Deadline Backsolve: Pace Plan | 日本語のまま | EN, JA |
| しずかTL for X | しずかTL for X | QuietTL – Chronological Feed | 日本語のまま | **JA のみ** |
| つづくToDo | つづくToDo 習慣化 | **日本語のまま** | 日本語のまま | JA |
| 禁酒ウォッチ | 禁酒ウォッチ｜断酒 | **日本語のまま** | 日本語のまま | JA |
| 起業おじさん | 起業おじさん | **日本語のまま** | 日本語のまま | — |
| ぱすてるオセロ | ぱすてるオセロ | **日本語のまま** | 日本語のまま | — |

### ここから読み取れること

1. **5本が英語圏で日本語の名前のまま売られています。**
   英語話者は検索でも見つけられず、偶然たどり着いても何のアプリか読めません。
   施策を打つ以前に、置いてあるだけの状態です。

2. **しずかTL for X は英語の掲載文なのに、アプリのUIは日本語だけです。**
   英語話者が「QuietTL」を買って開くと日本語画面が出ます。
   これは低評価に直結する組み合わせで、**海外施策より先に手を打つべき**です。
   掲載を日本語に戻すか、UIを英訳するかの二択になります。

3. **透けマルだけが本当に多言語対応しています。**
   ドイツ語の掲載名まで用意され、UIも5言語。海外で戦える唯一のアプリです。

## 戦略：どこに賭けるか

日本で使った「悩み検索の受け皿を作る」型は英語圏でも通用しますが、
**競合の数が桁違い**です。新規ドメインの英語SEOで上位を取るのは、日本語より遥かに厳しい。
したがって海外は配分を変えます。

| | 日本 | 海外 |
|---|---|---|
| 主軸 | サイト記事（悩み検索） | **ASO（App Store内検索）** |
| 従 | ASO | サイト記事（後回し） |

日本の実測では**流入の86%がApp Store内検索**でした。海外はサイトの土台が無い分、
この比率がさらに上がります。まずASOを整えるのが順当です。

### アプリごとの見立て

**◎ 透けマル — 海外の主戦場にする**

背景を透過する作業に言語は関係ありません。日本で見つけた「保存すると白くなる」問題は
英語圏でも同じように起きており（"transparent png saves as white"）、
しかも解決策を数値で示すアプリは見当たりません。多言語UIも揃っています。
**海外はここに集中します。**

**△ カエセル / シメキリ逆算 — 英語化しても勝ち目が薄い**

英語の掲載名は付いていますが、中身が日本の制度に強く依存しています。

- カエセルの核は変動金利の**5年ルール・125%ルール**。これは日本の住宅ローン慣行で、
  米英には無い概念です。英語圏のユーザーには意味がありません。
- シメキリ逆算の主用途は**同人誌の入稿**。海外にも同人文化はありますが、
  「入稿」を軸にした訴求は通りません。

英語掲載を作った労力は無駄ではありませんが、**ここに時間を追加投入しない**判断をします。

**× つづくToDo / 禁酒ウォッチ — 英語圏は競合が厚すぎる**

習慣化アプリと禁酒アプリは、英語圏では無料の巨大サービスが揃っています。
日本語掲載のまま置いておいても害はありませんが、勝つための投資はしません。

**要判断 ぱすてるオセロ** — Reversi は世界共通で言語依存もありませんが、
無料ゲームは競合が激しい分野です。英語掲載を作る価値はありますが優先度は低めです。

**要対応 しずかTL for X** — 前述のとおり、英語掲載×日本語UIは低評価を招きます。
海外施策としてではなく**リスク対処として**先に決着させます。

## 国別KPI

日本と同じ枠組みで測ります。目標値は日本（1アプリ1000ビュー）と同列に置かず、
**まず0を1にする段階**として設定します。

### 測る指標

| 指標 | 取得元 | 頻度 |
|---|---|---|
| 製品ページ表示回数（国別） | App Analytics の Territory 列 | 日次 |
| カテゴリ順位（国別） | `tools/check_ranks_intl.py` | 日次 |
| 評価数・評価（国別） | iTunes Lookup API（country 指定） | 日次 |

App Analytics のレポートには最初から `Territory` 列があるので、
**国別の集計基盤はすでに存在します**。2026-08-08 時点で観測された Territory は
すべて `JP` でした。海外からの流入は実質ゼロが出発点です。

### 段階目標（透けマル・US を先行）

| 段階 | 内容 | 判断 |
|---|---|---|
| 第0段階 | 英語のキーワード・スクリーンショットを整備 | 着手条件 |
| 第1段階 | US の製品ページ表示が**週10件**を超える | 検索に載り始めた |
| 第2段階 | 写真／ビデオ（有料）で**US 200位以内** | チャートに乗った |
| 第3段階 | US の表示回数が**日本の1割**に達する | 横展開を検討 |

第1段階に届かないうちは、GB / DE / AU へ広げません。
1か国で通用しない訴求は、他の国でも通用しないためです。

## 実行順序

1. **しずかTL for X の掲載を決める**（英語を下げる／UIを英訳する）— リスク対処なので最優先
2. **透けマルの英語ASOを作り込む** — キーワード・サブタイトル・スクリーンショット1枚目
3. `tools/check_ranks_intl.py` を日次に組み込み、国別のベースラインを取り始める
4. 第1段階を超えたら、英語の解決記事を書く
   （`transparent png saves as white` 系。日本語版がすでにあるので翻案でよい）
5. ドイツ語は透けマルのみ掲載済みなので、US で手応えが出てから DE を試す

## 注意

- 日本の記事をそのまま機械翻訳しない。英語圏の検索語は日本語の直訳ではない
- 順位・表示回数は必ずスクリプトで取得する。手で数字を書かない
- 掲載言語が日本語のままの国で順位を追っても意味がない。整備が先
